0 What & why

Static-assets mode shipped (Item 45): blobs can live in a host static folder instead of inside the workspace. But setting or changing that location is CLI-and-config-file only, read once at launch, and it doesn't move existing blobs — so pointing at a new folder makes every file show as missing until you hand-move the bytes and restart. That's a footgun and there's no in-app control at all.

This feature closes both gaps: a UI to change the location and a blob-migration step that moves the files with it. It also turns the nicb.at cutover's manual "edit config → git mv → restart" into one in-app action (§8).

1 Why this is safe — the manifest is location-agnostic

The manifest (media/manifest.json) stores only file_name → id per blob — never a path. The blob folder is resolved fresh each request from getGlobalFilesDir() (paths.ts:58). So:

  • Metadata is never at risk. Records, class memberships, and field values are keyed by manifest id — untouched by any file move.
  • "Missing" is just a derived flag. If the bytes aren't where the config points, reconcile flags them missing: true; put them there and the flag clears. Fully reversible.
  • The migration is a pure filesystem move of the bytes + a config update. No manifest rewrite is needed for the relocation itself (ids/filenames don't change).

That's what makes a one-click "change folder" viable: the risky part isn't the data model — it's doing the bulk file move safely (verify-before-delete) and persisting/applying the new location cleanly.

2 Decisions (proposed defaults)

Migration strategy
Move (default) · Copy (leave originals in place) · Leave (repoint only — "I already moved them"). The user's "configurably" ask — a radio in the change dialog.
Directions supported
classic→static, static→classic (turn it off), and static→static (relocate). All three are the same engine over oldDir → newDir.
Source of truth
The existing media-manager.config.json assets block — the UI rewrites it. The CLI already reads it; keep one source. (Needs the CLI to pass the config path to the server — see §4.)
Apply without restart
After a successful move, the server updates its own process.env.MEDIA_MANAGER_ASSETS_DIR live; getGlobalFilesDir() reads env every call, so the next request uses the new folder. No restart.
Authority for the move
By manifest, like export — only real blobs move; a shared static folder's foreign files (favicon, OG) are never touched.
Safety
Copy-then-verify-then-delete (move never deletes a source until its dest copy is confirmed). Manifest lock held for the operation. Abort — don't half-apply — on a destination name conflict.
v1 scope · no config
Full change+migrate in every launch mode. A config file is not required up front — serve never auto-writes one, so bare-path / MEDIA_MANAGER_ROOT launches have none. In that case the Storage dialog creates <root>/media-manager.config.json on first save (same as the config verb) and then applies live. So "no config" isn't a dead-end — setting a storage location is how you get your first config file, which is exactly what you'd want before committing the site anyway.

3 The migration engine

A new storage module — src/lib/storage/assetsMigrate.ts — with one primitive the API calls:

migrateBlobs({ toDir, strategy }): Promise<MigrateResult>
  // strategy: 'move' | 'copy' | 'leave'

Algorithm (under the manifest lock):

  1. Resolve fromDir = getGlobalFilesDir() (current) and the absolute toDir. No-op if equal.
  2. Preflight against the manifest: for each blob file_name, is it present in fromDir? Collect missingAtSource. Is there already a different file of that name in toDir? Collect conflicts. Check free space for copy/move. If conflicts (or, unless forced, missingAtSource) → abort before touching anything, returning the report.
  3. Transfer (skip for leave): for each blob, copyFile(from → to) then verify size; for move, unlink the source only after the dest copy verifies. Accumulate moved / copied / failed.
  4. Return a MigrateResult { fromDir, toDir, strategy, moved, copied, skipped, missingAtSource, conflicts, failed }. The caller persists + applies only on a clean result.
No manifest rewrite in the move itself. Because ids/filenames are unchanged, the manifest is already correct for the new location the instant the env flips. A reconcile on the next list confirms it (all present ⇒ nothing flagged).

MOVE

Bytes relocated; source emptied of manifest blobs. The default — "change the folder."

COPY

Bytes duplicated; originals remain (e.g. keep the in-workspace copy as a backup). Old dir becomes orphaned but intact.

LEAVE

No bytes touched — just repoint + persist. For when you already moved the files yourself (or are wiring up an already-populated folder).

4 Persist & apply (no restart)

Persist → the config file

  • In serve() always pass a config target: env.MEDIA_MANAGER_CONFIG_PATH = resolved.configPath ?? path.join(resolved.root, '${CONFIG_NAME}'). When a config already backs the session that's its path; when none does, it's the intended path at the workspace root — so the server always has a concrete file to write.
  • On a clean migrate, write that file's assets block (dir stored relative to the config file, for portability; null assets ⇒ remove the block = classic mode). If the file exists, rewrite in place preserving root + formatting; if it doesn't, create it with root (relative to its own dir) + the assets block — a first-class config, identical to what the config verb emits.
  • So persistence works in every launch mode; the only "session-only" case is a truly read-only filesystem (rare, surfaced as an error, not a silent no-op).

Apply → live env

  • Set process.env.MEDIA_MANAGER_ASSETS_DIR / _BASE_URL in the running server (or unset for classic).
  • getGlobalFilesDir() / isStaticAssetsMode() read env per call — the very next request serves from the new folder. No restart, no cache to bust.
  • Broadcast a refresh so open grids re-list (reuses the existing refresh bus).

5 API

EndpointDoes
GET /api/settings/storage Current state: { mode: 'classic'|'static', dir, baseUrl, blobCount, canChange, configPath, configExists }. configPath is always set (existing or the intended create-on-save target); configExists tells the UI whether the first save will create vs rewrite it. canChange=false only if that path isn't writable.
POST /api/settings/storage/preview Dry-run: given { toDir, baseUrl, strategy }, return the preflight report (blobCount, conflicts, missingAtSource, freeSpaceOk) without moving anything — powers the confirm dialog's summary.
POST /api/settings/storage Commit: run migrateBlobs, then (on clean result) persist the config + flip the live env. Returns the MigrateResult. Rejects with the report if preflight aborts.

All three are app-scoped settings endpoints, siblings of the existing /api/settings. A path-traversal guard validates toDir; the move is manifest-authoritative so it can't escape into unrelated files.

8 Does this make your site migration easier? — yes

Today's manual cutover: edit media-manager.config.json · git mv src/assets/…/media/files/* static/media/ · restart · then the reader-code change.

With this feature: open the editor on the workspace → Settings → Storage → set static/media + /media, strategy Move → one click relocates all 66 blobs, rewrites the config, and applies live. The two fiddly, error-prone steps (hand-moving files, editing the config) vanish.

Two things it does not do (by nature, not omission): it moves files on disk, so you still git add static/media && git commit (git staging isn't the tool's job); and it changes editor storage only — the reader/host-build change (drop the ?url glob, pass { assets: { baseUrl } }) is still a code edit in the site. So: materially easier, not fully automated.

9 Risks & edge cases

CaseHandling
partial Interrupted mid-move Copy-verify-delete means no source is lost before its dest exists; worst case is bytes in both dirs (copy done, unlink pending). Manifest is location-agnostic, so re-running the migrate (or a reconcile) recovers. No metadata risk.
conflict Name already in target Preflight aborts before any transfer with the conflicting names listed — never clobber a different file. (Same-content same-name ⇒ treated as already-there, skipped.)
missing Blob absent at source Reported; the move proceeds for the rest only if the user accepts (those stay missing until found). Mirrors doctor/export semantics.
orphans Copy / abandoned old dir Old bytes are never auto-deleted except by a confirmed move. After classic→static the empty media/files remains (harmless); after a copy the originals remain by design.
concurrency Move during editing Manifest lock + a "migrating…" state; single-user local tool, so contention is minimal.
no-config Launched without a config file Resolved: create-on-first-save. serve never auto-writes a config, so this is the common bare-path / env case — not an edge. First Storage save creates <root>/media-manager.config.json (root + assets), then applies live. The UI labels the button "Set location & create config" when none exists yet. One source of truth throughout.
picker Choosing the folder v1 = validated path input + resolved-path preview. A server-backed folder browser is a stretch (it's a local tool, so listing the FS is acceptable).

Rough size: P1 (engine + config write) is the substance and the only part with real failure modes; P2/P3 are thin over it; P4 is a bonus. No on-disk format change — the manifest is untouched; only the blob dir's location and the config's assets block move. Builds directly on Item 45's seam (getGlobalFilesDir / env plumbing).
