## Files, classes, and storage

**File-first model.** Files (blobs) are the primary entity; a **class** is a schema + opt-in per-blob metadata. The full design is [`docs/FILE_FIRST_CLASSES.md`](FILE_FIRST_CLASSES.md). On disk:

```
<root>/settings.json                                                       # app-wide UI prefs
<root>/media/{ manifest.json, files/, classes/<id>.json, settings.json }   # the hub (settings = classOrder + compression)
<root>/media/derived/<preset>/<name>                                       # generated compressed twins (Item 15)
<root>/globals/{ settings.json, data.json }                                # reserved `json` singleton (top-level)
<root>/records/{ settings.json, <typeId>/{ settings.json, data.json } }    # `json` record types (Item 18)
<root>/posts/{ settings.json, <collection>/<slug>.md }                     # Posts sub-app: markdown (Item 14)
```

| Concept     | Meaning                                                                                 | Storage                                                   | Repo                                              | UI                                                                                     |
| ----------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Blob        | A file in `media/files/`, identity = manifest `file_id` (UUID)                          | [`manifest.ts`](../src/lib/storage/manifest.ts)           | [`classRepo.ts`](../src/lib/storage/classRepo.ts) | All Files hub ([`files/+page.svelte`](../src/routes/files/+page.svelte))               |
| Class       | Schema + opt-in metadata keyed by `file_id` (any file type; empty schema = pure tag)    | `media/classes/<id>.json` = `{ schema, config, records }` | [`classRepo.ts`](../src/lib/storage/classRepo.ts) | Hub sidebar + [`FileEditorPanel.svelte`](../src/lib/components/FileEditorPanel.svelte) |

**Membership is opt-in and binary (by design):** a blob is a **member** of a class iff that class file has a record keyed by its id; **unclassified** = empty `classes[]`. There is **no** linked/unlinked/excluded tri-state, no `excludedFiles`, and **no per-extension gating** — any blob can belong to any class. The manifest's `classes[]` is a **derived cache**; class files are the source of truth. Consequences (all expected):

- **Add/remove to class** ([`addMembers`/`removeMembers`](../src/lib/storage/classRepo.ts)) writes the class file and updates `manifest.classes[]` atomically. Bulk add creates empty member records (fields filled inline later).
- **mtime-gated resync:** on list, if any class file is newer than the manifest, the index is rebuilt from class files ([`applyMembershipIndex`](../src/lib/storage/manifest.ts)) — catches hand edits.
- **Lazy heal:** every list reconciles the manifest against disk ([`reconcile`](../src/lib/storage/manifest.ts)) — new blobs get an id, vanished blobs are flagged `missing: true` (kept). Response carries `healed: { added, missing }`.
- **Rename** is **O(1)** ([`renameBlobById`](../src/lib/storage/classRepo.ts) → [`manifest.renameFileId`](../src/lib/storage/manifest.ts)) — disk + one manifest entry, no fan-out.
- **Delete from disk** drops the manifest entry and strips the member record from **every** class ([`deleteFromDiskById`](../src/lib/storage/classRepo.ts)). **Delete class** removes the file + strips its id from `classes[]`; blobs untouched.
- **Locking:** manifest mutations are atomic under one `.lock`, taken **before any class lock**.

**Filenames:** blobs use [`assertSafeBasename`](../src/lib/storage/filenames.ts) (any extension). Intrinsic image dims are backfilled into manifest entries on listing.

**Root discovery:** `MEDIA_MANAGER_ROOT` → [`getRootDir()`](../src/lib/storage/paths.ts). `listClassIds()` scans `media/classes/`; `listMediaTypeIds()` scans `records/` for `json` types and folds in the reserved top-level `globals`. The app reads **only** the current layout — [`hooks.server.ts`](../src/hooks.server.ts) runs a read-only [`assertCurrentLayout()`](../src/lib/storage/layoutGuard.ts) that fails every request with a "run upgrade-data" message on the pre-Item-18 flat layout (no dual-read).

**Reserved type ids:** only `globals` ([`RESERVED_TYPE_IDS`](../src/lib/storage/mediaTypes.ts), auto-created/healed by `ensureGlobalsGroupExists()`) — protected from create/rename/delete. The old `files` blob_store type is gone (`media/` is the hub). No reserved classes. **Reserved type-folder names** (`RESERVED_TYPE_FOLDER_NAMES`, rejected at slug time so a `json` type can't collide with a structural dir): `globals`, `media`, `records`, `posts`.

**Missing files:** a `file`-field value (or a class membership) referencing a blob absent from disk is surfaced globally via `GET /api/files/missing` ([`listMissingFileReferences`](../src/lib/storage/classRepo.ts)) and the hub's warning banner; class list items still carry `missing_file_fields: string[]` and records carry `_missing_files: { field → expected filename }`.

**Missing records:** a `record`-field value whose referenced record no longer resolves in its target type is annotated the same way (parity, not a global banner): class/record list items carry `missing_record_fields: string[]` and the record-detail read carries `_missing_records: { field → short id(s) }`, computed by [`recordRefs.ts`](../src/lib/storage/recordRefs.ts) (`resolveRecordRefs` reads each referenced target type once per request). The editor shows a per-field "record not found" hint + Clear via the shared `FieldInput`.

| Image compression (Item 15)                        | **Compressed twins alongside the originals, measured and reported.** A **preset** is a recipe (format + quality + an optional width) and things _subscribe_ to presets — a blob's derivative set is the **union** of its subscriptions, so a file in two classes with different settings has nothing to reconcile. Registry lives in `media/settings.json` (`compression`). **Subscriptions are the unit of choice:** the workspace subscribes (every image), and each **class** can subscribe on top (`ClassConfig.compressionPresets`, set in the class's `EntitySettingsDialog` → General). A blob's derivative set is `presetsForBlob()` — the union, in registry order. The inverse is the load-bearing half: leaving a class only drops a derivative when **no remaining** subscriber wants it, so `queue.pruneUnsubscribed` diffs against the resolved union, never one class's list. Membership writes and subscription edits both re-plan. Generation is automatic on ingest (**both** `registerBlob` callers: upload + Google Photos import) and never blocks the response; a **backfill** covers what's already on disk, is cancellable and resumable, and its state lives on the server so you can navigate away and back. Derivatives are written to `media/derived/<preset>/` (in static-assets mode, `<assetsDir>/derived/<preset>/`, so `baseUrl` composes) and recorded on the blob's manifest entry under `derived`. Generator rules: originals are **never** touched; `.rotate().keepMetadata()` so a phone photo's EXIF orientation and its ICC profile survive; a derivative bigger than its original is **discarded**; non-images are **recorded, not attempted**; every skip carries a `recipe` so it is never retried. Staleness is a **recipe comparison**, not a timestamp — changing a quality rewrites the recipe, marks derivatives stale and regenerates them **without asking** (originals are never at risk, so there is nothing to confirm). Quality is reported as **SSIM** (`ssim.ts`) — see the caveats note below. Filenames mirror the original's stem (clean + shareable), with a collision rule for two originals sharing one (`photo.jpg` + `photo.png`); every lookup reads `file_name` from the manifest and never reconstructs it. `/compression` reports savings, coverage, the SSIM histogram, a per-class breakdown and a flagged list, and offers a **sweep** for unreferenced files. Derivatives are served with an explicit 1-hour `Cache-Control`; versioned URLs are deferred (FUTURE_CHANGES Item 47). A preset may carry a **`width`**, downscaling (aspect preserved, never upscaled) — that is the responsive ladder, and its SSIM is computed against a **matched-size** original so the score is codec loss at that size, not the resize. Per-file detail lives in the editor's **Compression** section (`GET /api/files/[id]/compression`), and the grid's **Show** menu gains `file:saved` / `file:quality` / `file:presets` plus `saved`/`quality` sort keys, fed by the compact `FileItem.compression` summary (savings against one named preset; SSIM is the **lowest** across presets — the worst thing actually being served). ## HTTP API index (quick reference)

### Files / blobs (`/api/files/...`)

| Path pattern                                | Role                                                                                                                                                                                                                                                  |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/files`                            | All Files hub list (`FileListResponse`; `?query&classIds&match=all\|any&unclassified&groupByClass&groupByField&searchField&sort&dir`; carries `healed`)                                                                                               |
| `POST /api/files/upload`                    | Multipart upload (any type; HEIC→JPEG); registers the blob, returns `id`                                                                                                                                                                              |
| `GET /api/files/[id]/blob`                  | Raw blob bytes. `?preset=<id>` serves that preset's **compressed derivative** (Item 15), falling back to the original rather than 404ing; derivatives carry `Cache-Control: public, max-age=3600`                                                     |
| `GET /api/files/[id]/compression`           | Item 15 phase 2: one row per **subscribed** preset for this blob (generated/skipped/stale, sizes, SSIM, `src`) — the per-file editor's Compression section. Separate from the grid's `FileItem.compression` summary so a 400-tile masonry stays light |
| `POST /api/files/[id]/rename`               | Rename blob on disk + manifest (O(1)); body `{ new_filename }`                                                                                                                                                                                        |
| `POST /api/files/delete`                    | Bulk delete from disk; body `{ ids }` (strips member records across classes)                                                                                                                                                                          |
| `GET /api/files/[id]/metadata`, `.../strip` | EXIF read (now also carries `dimensionCheck` + `extensionMismatch`/`detectedFormatExtension`) / strip (`{ mode: 'all'\|'gps' }`)                                                                                                                      |
| `GET /api/files/[id]/dimension-check`       | Item 13: compare stored manifest dims vs the real (orientation-corrected) image; `{ stored, fileRaw, orientation, corrected, mismatch }`                                                                                                              |
| `POST /api/files/[id]/dimensions`           | Item 13: persist corrected/swapped intrinsic dims; body `{ width, height }` (positive ints)                                                                                                                                                           |
| `GET /api/files/[id]/extension-check`       | Item 12: compare the name extension vs the sniffed (magic-byte) type; `{ fileExtension, detectedExtension, mismatch }` (cheap, no exiftool)                                                                                                           |
| `GET /api/files/[id]/classes`               | Per-file editor sections: each class this blob belongs to + its schema/config/record (also the delete-usage surface)                                                                                                                                  |
| `GET /api/files/missing`                    | Global missing-files warning: dangling refs grouped per absent blob                                                                                                                                                                                   |

| Path pattern                   | Role                                                                                                                                                                                                                                                                                                                        |

## Residual notes

- **README** is the canonical place for install, **build + run** (`npm run build`, `node build`, `media-manager <root>`), and data layout examples.
- **`docs/FUTURE_CHANGES.md`** is the deferred-work backlog (non-committing ideas; do not treat it as the shipped feature set). `tasks.md` has been consolidated into it and is now just a pointer.
- **Title-by demotes the filename (by design, not a stale-name bug):** in a class **catalog** view with `config.displayField` set, the tile's prominent label is that title field (`title_value`) and the **filename is shown as a muted subtitle**. Renaming the blob therefore updates the subtitle, **not** the prominent label — which can read as "the name didn't update." It's working as designed; the filename only becomes the primary label in **All Files** or when no title-by is set. (Cross-reference staleness — where a _referenced_ entity's renamed title fails to refresh on other tiles — was the genuinely broken case and is fixed via the quiet refetch; see **Per-record editor**.)
- **`refreshTrigger` is the cross-surface invalidation bus, and it's cross-tab.** `src/lib/stores/refreshTrigger.ts` bumps a `writable` AND mirrors the bump over a `BroadcastChannel('media-manager-refresh')` so edits in one tab/sub-app invalidate overlapping views in **another tab** (the sub-app routes `/files` · `/media` · `/globals` are mutually-exclusive full-page chrome, so a producer and consumer are almost never co-mounted in one tab — the cross-app case is two tabs). The receiver bumps its local store **without** re-posting (no echo loop). Producers: any reference-affecting edit — blob/record rename, delete, title-by/linked-field edit (debounced on the autosave path), bulk op. Consumers (all do a **quiet** refetch, never mid-edit): the Files hub, Records hub, `GlobalsEditorPane` (only when idle — `!dirty && !saving`, which also swallows its own save's synchronous self-echo), and the `FilePicker`/`RecordPicker` (refresh their cached trigger labels so a renamed referent doesn't read stale until the dialog is reopened).
- **Bulk record ops preserve two-way links (data integrity, not just refresh).** `POST /api/media-types/[typeId]/records/bulk-delete` runs `unlinkRecordEverywhere` per id before deleting, and both `bulk-update` endpoints (`media-types/...` and `classes/[id]/...`) route each row through the link-aware wrappers (`updateTypeRecordLinked` / `updateClassRecordLinked`) — parity with the single-record paths. Previously the bulk paths wrote the data file directly, leaving the partner store with permanently dangling/contradicting id references. The bare `bulkUpdate*` repo helpers were removed.
- **Globals missing-ref badges recompute on save.** `POST /api/media-types/globals/record` re-reads via `getRecordById` so the response carries fresh `_missing_files`/`_missing_records` (parity with GET); the editor consumes them so fixing a broken reference clears the "Missing" hint immediately instead of leaving a false positive until reload.
- **The SSIM score is a ranking tool, not an absolute quality claim (by design).** [`ssim.ts`](../src/lib/server/compression/ssim.ts) uses a uniform **8×8** window where textbook SSIM uses an 11×11 Gaussian, and compares **luma only** — which systematically _over_-scores exactly the chroma-subsampling artifacts WebP introduces around q80. Both simplifications are fine for ranking files against each other (all the flagged list needs) and are why the number is presented as "needs a look", never as a published quality figure. More importantly it is **blind to the most likely real defect**: it compares the two buffers _as decoded_, so a derivative that lost its EXIF orientation and renders 90° rotated still scores ~0.99 — a perfect grade on a visibly broken image, and colour-profile loss is invisible for the same reason. That is why orientation + ICC preservation is a hard **generator rule** (`.rotate().keepMetadata()`) rather than something the metric is trusted to catch. For a **resized** preset the original is downscaled to the derivative's size first, so the score measures **codec loss, not the resize** — a 400px thumbnail at 0.96 is "a good 400px rendering", not "4% worse than the photo".
- **Compression writes are batched on purpose (not a durability shortcut).** Every grid read goes through `listAllFiles → reconcile`, which takes the **manifest lock**; `withFileLock` retries ~4.3s and then throws. A backfill acquiring that lock once per file would start failing user requests, and each write is an O(n) rewrite of the whole manifest. So [`queue.ts`](../src/lib/server/compression/queue.ts) accumulates results and flushes one write per batch, with encode concurrency bounded against **lock contention** rather than CPU count. A crash mid-batch loses at most that batch's records, which a backfill regenerates.
- **Data upgrade tool:** [`scripts/upgrade-data.mjs`](../scripts/upgrade-data.mjs) (`npm run upgrade-data -- <root>` or `... -- <root> --apply`) scans a data root and reports/applies the expected upgrades, culminating in the **file-first reorg** (step 5): relocate `files/` → `media/files/`, rebuild the manifest at `media/manifest.json` (v2, with derived `classes[]`), and convert each `images`/`generic` catalog folder → `media/classes/<id>.json` (`{ schema, config, records }`, dropping `image_name`/`excludedFiles`); the `blob_store` `files` type dissolves; `json`/`globals` folders stay. Idempotent (skipped once `media/classes` exists), dry-run by default.
